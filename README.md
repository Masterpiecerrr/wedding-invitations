# 中式婚礼请柬

一个可以在微信里转发的中式婚礼请柬网页，配色是胭脂红、宣纸和泥金。
页面上**所有文字、日期、照片、音乐、模块顺序**都在 `wedding.config.ts` 这一个文件里改。

页面结构：却扇开场（团扇移开见新人）→ 首屏（封面照、倒计时）→ 婚书 → 婚礼仪典（红绸长卷）→ 礼俗小笺 → 锦书留影 → 喜宴华章 → 吉日良辰（日历、地址、导航、保存请柬图片）→ 敬候佳音（腾讯问卷）→ 恭候光临（撒喜糖）。

> 新人姓名里加空格（如 `禹   露`）不影响什么：系统会自动去掉空格，页面上两人名字自动等宽对齐，微信卡片里也不带空格。

---

## 一、改信息

打开根目录的 **`wedding.config.ts`**，只改 `'单引号'` 里面的内容。每一项都有中文注释。

- **日期**写成 `'2027-05-01'`。星期、农历、日历、倒计时、中文日期都会自动算出来。
- **模块顺序**里删掉哪项，页面上就不显示；调换顺序，页面也跟着换。
- **故事、问答、相册、流程**的条目数量随意，复制或删除一整段 `{ ... }` 就行。

## 二、换照片

1. 把照片放进 **`photos`** 文件夹。用手机原图就行，打包时会自动压缩。
2. 在配置里填文件名，例如 `照片: '封面.jpg'`。还没选好就写 `''`。
3. 裁剪切到了脸，就写成 `{ 文件: '封面.jpg', 焦点: '50% 30%' }`：第一个数字是左右位置，第二个是上下位置，数字越小越靠左、越靠上。

**想知道每个照片位置在页面哪里？** 在网址后面加上 `?看位置`，例如 `https://你的域名/?看位置`。每张图上都会标出它在配置里对应哪一项。

> 婚书配图、故事配图、酒店照片留空时会直接隐藏；首屏照片和相册留空时会显示「待放照片」占位。

## 三、换音乐

把 mp3 放进 **`music`** 文件夹，在配置的 `音乐.文件` 里填上文件名。留空就不显示音乐按钮。
宾客轻触团扇的那一下会开始播放音乐，右上角的唱片按钮可以暂停。

## 四、赴宴回执（腾讯问卷）

在 [腾讯问卷](https://wj.qq.com) 建好问卷，把链接填到 `回执.问卷链接`。建议问这几题：

1. 您的姓名（填空，必填）
2. 是否出席（单选：准时出席 / 很遗憾无法到场）
3. 出席人数（单选：1 人 / 2 人 / 3 人 / 4 人及以上）
4. 是否需要儿童座椅（单选）
5. 饮食忌口（填空，选填）
6. 想对新人说的话（填空，选填）

## 五、本地预览（可选）

需要先安装 [Node.js 22](https://nodejs.org/zh-cn)，然后在这个文件夹里打开终端：

```sh
npm install      # 第一次运行时执行
npm run dev      # 浏览器打开 http://localhost:5173 ，改了配置或照片会自动刷新
```

## 六、部署到网上（Cloudflare Pages）

1. 注册并登录 [Cloudflare](https://dash.cloudflare.com)。
2. 依次进入 **Workers & Pages → 创建 → Pages → 连接到 Git**，选择这个 GitHub 仓库。
3. 构建设置这样填：

   | 项目 | 填写 |
   | --- | --- |
   | 框架预设 | 无（None） |
   | 构建命令 | `npm run build` |
   | 构建输出目录 | `dist` |

4. 点「保存并部署」，大约 2 分钟后会得到一个 `xxx.pages.dev` 网址，可以先发给自己测试。
5. **绑定正式域名**（推荐买 `.com`）：在 Pages 项目的「自定义域」里添加域名，按提示操作。
6. 绑好以后，把配置里的 `分享.网址` 改成你的域名，保存即可。

以后每次修改并推送到 GitHub（在 GitHub 网页上直接编辑、上传照片也算），Cloudflare 都会自动重新发布，1～2 分钟后生效。

## 七、微信卡片（标题、描述、缩略图）

都在 `wedding.config.ts` 的 `分享` 里改：

| 项 | 作用 | 留空时 |
|---|---|---|
| `标题` | 卡片第一行粗体字 | 「新郎 & 新娘 · 婚礼请柬」 |
| `描述` | 卡片下方灰色小字（微信大约显示两行） | 日期 + 酒店 +「诚邀您见证我们的婚礼。」 |
| `缩略图` | 卡片右侧的小方图 | 首屏照片自动加「囍」字和名字 |

- 换缩略图：把图片放进 `photos` 文件夹，写文件名，如 `缩略图: '分享图.jpg'`。会自动裁成正方形、压到 600×600，不叠加文字；位置不合适可写 `{ 文件: '分享图.jpg', 焦点: '50% 40%', 缩放: 1.2 }`。缩略图显示很小，选人物近、背景简单的图效果最好。
- 改完提交，等一两分钟网站更新。**微信按网址缓存卡片**：要换一个新网址才会重新抓取，把 `?v=6` 改成 `?v=7`（数字递增）重新生成二维码，扫码打开后点「⋯」→「转发给朋友」。已经发出去的卡片不会变。
- 直接粘贴网址只会显示一行文字，一定要扫码打开后再转发。


## 八、撒喜糖全场计数

结尾「撒喜糖」按钮下方会显示全场累计：「已有 N 把喜糖撒向新人」。所有宾客撒的都加在一起。

- 文案在配置的 `结尾.喜糖计数` 里改，`{n}` 处显示数字；留空 `''` 就不显示计数，撒糖照常。
- 计数存在 Cloudflare 的 D1 数据库 `wedding-sweets` 里，接口代码在 `functions/api/sweets.js`。
- 计数服务出问题或当天免费额度用完时，数字自动隐藏，撒糖和请柬其他部分不受影响。
- 防刷：连点会合并上报，单次最多算 12 把。

**清零**（正式发请柬前建议清一次，去掉测试时撒的数）：
1. 登录 Cloudflare，左侧进入 **存储和数据库 → D1 SQL 数据库**，点 `wedding-sweets`。
2. 打开 **控制台** 标签，输入下面这句，点 **执行**：
   ```sql
   UPDATE sweets SET count = 0;
   ```
3. 想看当前是多少：执行 `SELECT count FROM sweets;`

**查看用量和剩余额度**（免费额度每天北京时间 8 点重置）：
- 数据库：**D1 SQL 数据库** 列表页顶部有当天「已读取行 / 5M」「已写入行 / 100k」；点进 `wedding-sweets` 的 **概述** 可看每天的曲线。
- 接口调用次数：**Workers 和 Pages** 概览页可看当天请求数（每天上限 10 万次，只有撒糖和读数会计入，打开请柬不计）。

## 九、正式发出前的清理清单

1. **计数清零**：见上面第八节，执行 `UPDATE sweets SET count = 0;`，再用 `SELECT count FROM sweets;` 确认是 0。测试地址和正式网址共用同一个数据库，所以最好在最后一次测试完之后再清；发出去之后自己别再点「撒喜糖」。
2. **删测试分支**（可选，不影响正式站）：GitHub 仓库 → **Branches**，删掉 `liyi`、`quexian`、`yidian`、`xitang`、`gh-pages` 等用完的分支。它们对应的 `xxx.wedding-invitations-9uy.pages.dev` 预览地址也会随之失效。
3. **清旧预览部署**（可选）：Cloudflare → **Workers 和 Pages** → `wedding-invitations` → **部署**，把不用的预览部署删掉；也可以把以前试验用的 workers.dev 小项目一并删除。
4. **最后过一遍**：用手机扫二维码打开正式网址，检查音乐、照片、文字、导航、回执链接；再用微信扫码转发一次，确认分享卡片是最新的（改了卡片内容后，在网址后加 `?v=数字` 换一个新数字，微信才会重新抓取）。
